2026-08-23 Decision (CORE-2): All archive mutations follow one writer protocol — acquire `<archive>.lock` (mkdir-based, cross-process) → re-stat and reload if the file changed on disk → plan additions PURELY against a draft index → persist (append: open-append + write + fh.sync(); rewrite: sibling temp + fh.sync() + atomic rename + parent-dir fsync) → only then mutate in-memory state. Reason: a persist failure must leave memory matching disk so retries re-plan identically; atomic rename means a crash leaves either the old or new complete file and readers of the old inode finish safely; the same lock in `scripts/archive-daily-local.sh` makes publishes mutually exclusive with app appends. In-process appends serialize behind one promise chain.

2026-08-23 Decision (CORE-2): Durability honesty about fh.sync() on macOS. `fh.sync()` is fsync(2); on APFS that is not F_FULLFSYNC, so it buys crash-atomicity and torn-tail recovery but NOT guaranteed power-loss durability. The parent-dir fsync covers directory-entry creation/rename durability to the same standard. We accept this because the archive is rebuildable from retailers and the alternative (F_FULLFSYNC via fcntl) has no zero-dependency Node API.

2026-08-23 Decision (CORE-2): Torn-tail policy for loads. Newline-terminated lines must decode AND pass the v2 envelope check, else hard error naming filePath:lineNumber (even when it is the last line) — corruption never passes silently. An UNTERMINATED final fragment that decodes is recovered as a record (a crash happened between write and newline); one that fails JSON.parse or the envelope check sets a private torn-tail flag: queries still work over the good prefix, but append()/compact() refuse until repair (`scripts/repair-archive.js`), so a bad fragment can never be glued into a "valid" line. Stored hashes are re-verified against recomputed fingerprints at load; mismatches are collected as defects (getLoadDefects()), not fatal — the data still serves while repair rewrites corrected hashes. Snapshot offersHash is NOT recomputed at load (deriving it requires replaying listing state across all prior snapshots — costly and fragile against mid-archive corruption).

2026-08-23 Decision (CORE-2 M1, bd8ae37): Canonical hashing sorts object keys with localeCompare(key, "en") — locale-pinned, so digests are identical on every machine (the previous locale-less sort was machine-dependent). Adopted only after proving byte-parity with the old comparator across pinned-digest fixtures and all 18,726 v2 records then in data/prices.jsonl (0 digest diffs; archive key sets are ASCII where both orders agree). Archive dedup depends on hash equality across runs; do not change this without a migration plan.

2026-08-23 Decision (CORE-2 review round): The archive lock is deliberately FAIL-FAST across processes — a held `<archive>.lock` throws immediately; there are no wait queues or blocking retries. Correctness comes from re-stat-reloading the file under the lock (writers re-read disk truth after acquiring), not from waiting, so a fail-fast refusal is always safe and waiting would only add deadlock/timeout complexity without strengthening guarantees. Waiting with timeout + retry remains a future need if multiple human-driven writers become routine; the design groundwork exists via the lock dir's `pid` file (stale-holder recovery) plus the recorded mtime of acquisition.

2026-08-23 Decision (CORE-2 review round): `getLoadDefects()` reflects only the most recent COMPLETED load of that repository instance and can go stale after an external repair or another writer's rewrite — the instance has no cross-process invalidation channel by design. Operators checking hash-defect reports should either construct a fresh instance after running repair (its report lists corrected defects) or rerun verification against the rewritten archive. Long-lived servers that need fresh defect state are the caller's responsibility to reload/restart; the repository intentionally stays a thin, honest window onto the file.
